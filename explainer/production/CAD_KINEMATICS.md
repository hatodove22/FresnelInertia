# 実CADに基づく説明用の機構リグ

`public/models/device-kinematics.json` は、Fusion **VRSJ2026 v30** の回転ジョイント、円筒面、歯形、部品配置を読み出して作成した。フィンの回転支点はサーボ軸より外側に約20 mm離れる。メッシュのbounding box中心を回転支点に使用していない。

このリグはCADの形状を用いた運動説明であり、実機の運動計測、サーボ校正、可動範囲・干渉・触覚効果の検証ではない。元CADに残る旧コントローラや省略部品については [CAD_ASSETS.md](CAD_ASSETS.md) を参照。

## 入力と座標

- 入力 `contactPadAngleRad` は**パッド自身が元CAD +Z軸まわりに右手則で回る角度**。ゼロはGLBのエクスポート姿勢。
- `fin` の `ratio = +1`、`driver` の `ratio = −1`。`driver` はピニオン、出力ホーン、ホーン保持ねじを含む。
- 各グループの軸は `[0, 0, 1]`。左ジョイントの元表現 `[0, 0, −1]` を表示の共通軸へ正規化している。CADのジョイント角やファームウェアのサーボ指令値を直接入力する仕様ではない。
- `left` は元CAD −X側のパッドA、`right` は＋X側のパッドB。親指／人差し指、ファームウェアch0／ch1への対応は未確認。
- 同相は両パッドに同じ符号の角度、差動は反対符号の角度。±8°は説明用振幅の提案であり、実機の限界値ではない。

GLBの頂点は、各部品のローカル座標をFusion occurrence `transform2`でワールドへ写し、次の処理だけを加えたもの。CAD XYZの回転は行っていない。

```text
centerCm = [-0.04999990463256854, 0.20163881544307705, -0.2014983887698012]
pMeters = (pWorldCm - centerCm) * 0.01
pAnimated = pivot + R(axis, ratio * contactPadAngleRad) * (pRest - pivot)
```

メッシュは既にワールド中心座標で格納されている。Three.jsでグループを組む場合は `T(pivot) R T(−pivot)` と同等にし、元頂点を二重に平行移動しない。元のGLB姿勢をゼロ角で厳密に復元すること。`nodeIndices` はGLB `nodes` 配列のインデックスで、Three.jsオブジェクトIDやmeshインデックスではない。GLTFLoaderの名前サニタイズを避けるため、parser associationの `nodes` を使って対応させる。

## 支点と可動部品

数値はm、中心移動済みの元CAD XYZ。支点のZ座標は同じ無限軸上の代表点としてピニオン原点の平面を選んでいる。

|---|---:|---:|---:|---:|---|
| A / fin | −0.03150000095367432 | −0.0020163881544305955 | 0.024014983887698016 | +1 | 37 |
| A / driver | −0.011500000953674316 | −0.0020163881544305955 | 0.024014983887698016 | −1 | 4, 8, 9, 35 |
| B / fin | 0.03149999985843898 | −0.002022187500322694 | 0.024014983887698006 | +1 | 38 |
| B / driver | 0.011499999046325687 | −0.0020163881544305938 | 0.02401498388769802 | −1 | 21, 25, 26, 36 |

| 部品 | ノード | 対応 |
|---|---|---|
| `fin:1/ボディ1` | 37 | Aフィン全体 |
| `fin:4/ボディ1` | 38 | Bフィン全体 |
| `pinion:1/ボディ1` | 35 | Aピニオン |
| `pinion:3/ボディ1` | 36 | Bピニオン |
| `XL,XC-330 v1:1+DC15_A01_HORN_DUMMY:1/ボディ1` | 4 | A出力ホーン |
| `XL,XC-330 v1:2+DC15_A01_HORN_DUMMY:1/ボディ1` | 21 | B出力ホーン |
| `XL,XC-330 v1:1+BTS2_M2_6X8:1/ボディ1`, `ボディ2` | 8, 9 | Aホーン保持ねじ |
| `XL,XC-330 v1:2+BTS2_M2_6X8:1/ボディ1`, `ボディ2` | 25, 26 | Bホーン保持ねじ |

保持ねじの追従は同軸の取付形状に基づく。ねじを含む機械的固定の独立した実測や、CAD rigidGroupによる確証はない。サーボのケース・カバー・ケースねじ・コネクタ、四つのHapticReactor、周辺構造、コントローラなど残り47ノードは固定する。振動チャンネルを説明するときに、トランスデューサをこのフィン機構と一緒に回転させない。

## 値の根拠

**K01 — ライブの読取専用エクスポート。** 2026-09-06 01:13（ローカル時刻）に、既存の手動登録 `FusionExplainerExport` を介してAPI getterのみを実行した。結果は [fusion-kinematics-raw.json](../../output/explainer-assets/fusion-kinematics-raw.json)。CADには回転ジョイント3個、as-built joint 0個、motionLink 0個が存在した。文書の `isModified` は実行前後とも `true` で、ウィンドウにも作業開始前から未保存の `*` があった。文書の編集・保存・回転駆動をしていない。任意プロパティの未対応は `...Error` に記録しているが、エクスポート本体の例外リストは空。

**K02 — フィン支点。** `回転 2` は `occurrenceOne = fin:1` を返し、`geometryOneTransform`の原点は `[-3.2, 0, 2.2]` cm、回転軸は−Z。フィンのネイティブ円筒面tempId 6, 10, 21, 28は `[-2, 0, 0.3]` cmを通るZ軸、半径0.875 cmを共有する。`fin:1`の配置を適用するとこの軸がジョイントと一致する。`fin:4`は同じネイティブ形状を約Z180°回転して配置したものなので、同じローカル支点 `[-2,0,0]` cmにその正確な `transform2` を適用した。元配置の約−0.005799 mmのYずれも保持した。残る `回転 3` と `回転 4` はoccurrence参照がnullで、返す位置も右フィン支点と一致しないため、右側の拘束根拠には採用していない。

**K03 — ホーンとピニオン軸。** ピニオン円筒面tempId 6, 38, 152はネイティブ原点 `[0,0,0]` cmを通るZ軸を共有する。ホーン円筒面tempId 6, 7, 8, 17, 22, 29の軸はネイティブYであり、occurrence変換後はCAD Zになる。A側はワールド `x=−1.2, y≈0` cm、B側は `x=1.1, y≈0` cmでピニオンと同軸。ホーン保持ねじの主円筒も同軸である。サーボアセンブリ全体を可動扱いにする根拠はない。

**K04 — 伝達比と回転符号。** フィンはセクタ歯車形状。両歯形で歯元半径0.875 cm、歯先半径1.1 cmが一致し、歯先面のサンプル点は18°間隔に並ぶ。例えばピニオンtempId 135, 127, 121の角度は19.15°, 37.15°, 55.15°、フィンtempId 142, 148, 156は7.85°, 25.85°, 43.85°。後者の角度はネイティブ支点 `[-2,0]` から計算する。これは全周換算で20歯相当のピッチを示すが、現物形状が完全な20歯の輪であるという意味ではない。軸間距離約2 cmで等しい歯の間隔・半径をもつ外歯車として、公称の等角・逆方向回転 `θfin = −θpinion` を説明に使う。**伝達比は形状からの推論であり、CAD motionLinkや実測値ではない。** 歯の接触をソルバで駆動して検証していない。

**K05 — ノード・座標対応。** [device-cad-metadata.json](device-cad-metadata.json) と実GLBの `nodes` を照合した。各可動グループは元の正確な部品名とnode indexを両方持ち、上の座標変換を共有する。元CADの軸はファームウェアの校正済みbody frameを意味しない。

## 再現と検証

- 読取コード: [FusionKinematicsReadOnly.py](../../output/explainer-assets/FusionExplainerExport/FusionKinematicsReadOnly.py)。APIプロパティの参照とローカルJSON出力のみ。CADへのsetter、タイムライン移動、保存、接続やサーボ駆動は含まない。
- 実行に使用したローカルwrapperは [FusionExplainerExport.kinematics-runner.py](../../output/explainer-assets/FusionExplainerExport/FusionExplainerExport.kinematics-runner.py) に残した。既存の登録済み `FusionExplainerExport.py` はエクスポート後に元のメッシュエクスポータへ戻している。自動実行設定は変更していない。
- 生成・整合性確認: `python output/explainer-assets/build_kinematics_metadata.py`。元JSONとメッシュメタデータからリグを再生成し、実GLBとの名前一致、10可動ノードの重複なし、47固定ノード、単位軸、cm→m座標換算を確認した。
- `output/explainer-assets/`内のFusion生データと読取コードはローカルの調査証拠。映像の再現には配布GLB、リグJSON、共有ビューアを使用し、Fusionの再エクスポートを必要としない。
- この作業でのCAD編集・保存、ファームウェア変更、USB/シリアル接続、実機駆動はゼロ。ブラウザ／映像での見え方は制作側で別途確認する。

### 実GLBを使った自動回帰確認

[device-rig.test.mjs](../tests/device-rig.test.mjs) はNode上のGLTFLoaderで実GLBとリグJSONを読み、productionの `DeviceRig` / `mechanismMotion` を検査する。WebGLや画面の代替モデルは使わない。

- 57メッシュの全頂点について、回転グループへの再親子化前後とゼロ入力時のワールド位置が一致。
- 左右を独立に±10°入力し、実フィン37/38の正回転と実ピニオン35/36の逆回転を頂点の符号付き角度で確認。
- 全可動頂点の支点軸からの距離と軸方向高さが不変。固定47ノードのワールド変換は、四つのパルスを変化させても不変。
- 200回の異なる姿勢入力後、全頂点が元のゼロ姿勢へ戻り、累積ドリフトなし。
- 非有限入力の無効化、パッド角の±10°制限、四つのパルスの0〜1制限、入力オブジェクトを変更しないこと、同相／差動の符号、パルスのチャンネル切替と周回境界を確認。

座標比較の許容誤差は `1e−12 m`。既存頂点への倍精度の剛体変換を比較する数値テストの許容差であり、CADや実機の寸法精度を主張する値ではない。`npm test` は追加7件と既存8件、合計**15件成功・0件失敗**。この結果に実機の駆動、歯の接触、可動域、触覚効果の検証は含まれない。
